## 【1】お客さんに迷惑がかかるかもしれない話

### ① 2人が同時に使うと、他人のプリントが届く  ✅ 対応済み（2026-08-31）

> 再現・原因分析・対策案の比較・実装・検証の記録は
> `docs/incident/2026-08-31-race-condition.md` にまとめてある。


`src/main.py` は PDF を作るとき、必ず `output.tex` → `output.pdf` という同じ名前の
ファイルを作っている。サーバーは1台しかないので、A さんの処理中に B さんが
ボタンを押すと、B さんが A さんのファイルを上書きし、A さんの画面に B さんの
プリントが表示される。（まな板が1枚しかない台所と同じ）

**直し方**：注文が来るたびに使い捨ての作業フォルダを作り、そこで PDF を作って、
渡したら捨てる。Python 標準の `tempfile.TemporaryDirectory()` を使う。
`platex` には `-output-directory` でそのフォルダを指定する。

### ② 100枚制限が実は効いていない

`frontend/app/page.tsx` の100枚チェックはブラウザの中だけの判定。
URL を直接叩けば無制限に注文できる。

```
https://math-generator-backend.onrender.com/api/generate?num_prints=99999
```

無料プランの Render が固まって落ちる。

**原則**：画面側のチェックは「ユーザーへの親切」、サーバー側のチェックが「本当の防御」。
両方に書く。

```python
from fastapi import Query

def generate_pdf(
    num_problems: int = Query(10, ge=1, le=50),
    num_prints: int = Query(1, ge=1, le=100),
):
```

`ge=1, le=100` は「1以上100以下」の意味。

### ③ どのサイトからでも呼べる状態になっている

`src/main.py`：

```python
allow_origins=["*"],  # 開発中はどこからでもアクセス可能にする
```

CORS は「どのサイトからこのサーバーを呼んでいいか」の許可リスト。`*` は全部OK。
コメントには「開発中は」とあるが、もう本番公開済み。
このままだと他人が自分のサイトを作ってこのサーバーを裏で使える（サーバー代はこちら持ち）。

```python
allow_origins=[
    "https://math-generator-puce.vercel.app",
    "http://localhost:3000",
],
```

### ④ エラーが起きても「成功」として返ってしまう  ✅ 対応済み（2026-08-31）


```python
except Exception as e:
    return {"error": f"PDFの作成に失敗しました: {str(e)}"}
```

ウェブには成功・失敗を表すステータスコードがある（200=成功、404=なし、500=サーバーエラー）。
上のコードは失敗内容を 200（成功）で返しているので、画面側の `if (!response.ok)` は
成功と判断し、PDF でないものを PDF として開こうとする。

さらに LaTeX が「何行目の何が悪いか」を書いた `output.log` を捨てているので原因が分からない。
これは今後いちばん困る。

**直し方**：

```python
result = subprocess.run([...], capture_output=True, text=True)
if result.returncode != 0:
    raise HTTPException(status_code=500, detail=result.stdout[-2000:])
```

## 【2】これから単元を増やすときに詰まる話

### ⑤ 画面で選んだ単元がサーバーに届いていない ★構造上いちばん大きい問題

画面は「数学I → 二次関数 → 二次方程式と二次関数の関係 → 共有点の座標」と
4段階選ばせているのに、サーバーへ送っているのはこれだけ。

```
/api/generate?num_problems=10&num_prints=1
```

選んだ単元の情報がどこにも入っていない。サーバーは常に同じ1種類の問題を作る。
今は実装済みが1種類だけなので誰も気づかないが、2種類目を作った瞬間に
「選んでも同じプリントが出る」状態になる。

**直し方**：送る情報を増やす。

```
/api/generate?problem_type=quadratic_x_intercepts&num_problems=10
```

サーバー側に「合言葉 → 使う関数」の対応表（辞書）を持つ。

```python
GENERATORS = {
    "quadratic_x_intercepts": generate_quadratic_problem,   # いまあるもの
    "factorization_basic":    generate_factorization,       # これから作るもの
}

func = GENERATORS[problem_type]
p = func()
```

これをやっておくと、単元を1つ増やす作業が
「関数を1個書いて、辞書に1行足す」だけになる。
やらないと `if 単元 == "..." elif ...` が延々と続く巨大なコードになる。

### ⑥ 「LaTeX テンプレートに流し込む」が実はできていない

プロジェクトの説明は「用意していた LaTeX ファイルに流し込む」だが、
実際は LaTeX の中身が `src/main.py` に直接書き込まれていて、
`latex_templetes/templete1.tex` はプログラムから一度も読まれていない。置いてあるだけ。

問題形式が50種類になると `main.py` に50個分の LaTeX 文書が積み上がる。
「余白を3cmに直したい」と思っても50か所探すことになる。

**直し方**：`.tex` 側に目印を書いておき、Python は置き換えるだけにする。

```latex
% templates/problem_sheet.tex
{\large \textbf{ __TITLE__ }}
問題: __INSTRUCTION__
\begin{enumerate}
__PROBLEMS__
\end{enumerate}
```

```python
tex = open("templates/problem_sheet.tex", encoding="utf-8").read()
tex = tex.replace("__TITLE__", "二次関数 グラフと$x$軸の共有点")
```

まずはこの `replace` で十分。慣れたら Jinja2（テンプレート専用の道具）に移ればよい。

**注意**：これをやると `Dockerfile` の修正も必要。
いま `COPY src/ ./src/` しかないのでサーバー上にテンプレートが存在せず落ちる。

```dockerfile
COPY latex_templetes/ ./latex_templetes/
```

### ⑰ テストが1つもない

テストとは「プログラムがプログラムを検査する仕組み」。

自動生成のプログラムはテストが最も効く種類のコード。
今のコードにも特殊ケース対応が入っている。

## 補足：git の差分が全ファイル変更に見えるとき

ファイルの改行コードがワーキングツリー上 CRLF、コミット済みが LF になっている。
Windows 側の git（VS Code）は自動で変換するので差分ゼロだが、
Linux 側の git から見ると全行が変更扱いになる。

本当の差分はこれで確認する。

```bash
git diff --ignore-all-space --stat
```

恒久対策としてルートに `.gitattributes` を置くとよい。

```
* text=auto eol=lf
*.png binary
*.pdf binary
```

## ⑲ subprocess に stdin と timeout を渡していない

`capture_output=True` が横取りするのは stdout / stderr だけで、**stdin は素通り**する。
そのため platex が入力待ちに入ると、リクエストが終わらなくなる。

実際に、`-interaction=nonstopmode` をタイプミスした場合に起きうる。
TeX は未知の値を警告して無視し、既定の `errorstopmode`（エラー時に人間の入力を待つ）で続行するため。

しかも本番（Render）にはターミナルが無いので即座に失敗する。
**手元ではハングし、本番では失敗する**という環境依存の挙動になり、原因究明が難しい。

**直し方**：

```python
subprocess.run(
    ...,
    capture_output=True, text=True, errors="replace",
    stdin=subprocess.DEVNULL,   # 何を聞かれても即 EOF。待たない
    timeout=60,                 # 万一止まっても強制終了
)
```

サーバーから外部コマンドを呼ぶときの定石。
