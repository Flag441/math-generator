# 高校数学演習問題自動生成アプリケーション

私が塾講師として勤務していた際に個人用として使用していた、演習問題を自動生成するコードをブラッシュアップし、
WEBアプリケーション化してだれでも利用できる形にしました。

## 本番環境URL
- **フロントエンド (公開サイト)** : https://math-generator-puce.vercel.app
- **バックエンド (APIサーバー)** : https://math-generator-backend.onrender.com

無料のサーバーを利用しているため、最初のPDF生成には1分弱要します。

## 主な機能
科目、単元、小単元、問題タイプをステップ形式で選択。選択した問題の数値部分をランダムに変更し、複数問を配置した演習プリントを自動で生成します。

## 技術スタック

### フロントエンド
- **フレームワーク** : Next.js (TypeScript) / App Router
- **スタイリング** : Tailwind CSS
- **ライブラリ** : React-KaTeX (数式レンダリング)
- **ホスティング** : Vercel

### バックエンド
- **言語** : Python 3.10
- **フレームワーク** : FastAPI
- **PDF生成** : LaTeX (pLaTeX / dvipdfmx)
- **ホスティング** : Render

### インフラ・その他
- **コンテナ** : Docker / Dockerfile (コンテナ環境内で日本語LaTeXの環境構築を自動化)
- **ソース管理** : Git / GitHub

## 技術スタックの選定理由

### フロントエンド

- **Next.js (TypeScript) / App Router**
科目・単元・問題タイプと階層的にドロップダウンを絞り込む複雑なUIにおいて、TypeScriptによる型安全な状態管理がバグの発生を防ぐために不可欠でした。また、App Routerの採用により、コンポーネントの分割と直感的なルーティングを両立できる点から、単なるReact(SPA)ではなくNext.jsを選定しました。

- **Tailwind CSS**
CSSファイルとコンポーネントを行き来するコンテキストスイッチを無くし、開発スピードを最大化するためです。標準のユーティリティクラスを組み合わせるだけで、ボタンのホバー時の挙動やローディングアニメーションなど、モダンでユーザーフレンドリーなUIを迅速に実装できました。

- **React-KaTeX**
数式レンダリングライブラリとして有名なMathJaxと比較して、KaTeXは描画スピードが圧倒的に高速です。ユーザーが問題を選択した瞬間にストレスなく数式のプレビューを表示させるUX（ユーザー体験）を優先し、こちらを採用しました。

### バックエンド

- **Python 3.10**
数式の文字列処理やランダムな数値生成などにおいて扱いやすく、将来的に高度な数式処理ライブラリ（SymPyなど）を導入した拡張を行う際にも、数学的処理に強いPythonが最も適していると判断しました。

- **FastAPI**
FlaskやDjangoと比較して非常に軽量・高速に動作し、非同期処理にも対応しているため。また、型の定義から自動的にAPIドキュメント（Swagger UI）が生成されるため、フロントエンド側（Next.js）との通信連携を迷わずスムーズに実装できる点が個人開発において大きなメリットでした。

- **LaTeX (pLaTeX / dvipdfmx)**
HTMLからのPDF変換（wkhtmltopdfなど）では、ルートや分数を含む複雑な数式が崩れてしまいます。教育現場で実際に生徒へ配布する「商用・実用レベルの美しい数式組版プリント」を実現するには、学術界のデファクトスタンダードであるLaTeX以外の選択肢はありませんでした。

### インフラ・その他

- **Docker**
日本語対応のLaTeX環境は依存関係が複雑で、ファイルサイズも数GBに及びます。この重厚な環境を直接OSにインストールすると、「開発環境（自分のPC）では動くのに、本番環境では動かない」という環境差異のトラブルに直結します。Dockerfileで構築手順をコード化（IaC化）することで、どこでも必ず同じLaTeX環境が立ち上がる堅牢なシステムを作るために必須の選択でした。

- **Vercel / Render**
VercelはNext.jsの開発元であり、ゼロ設定でフロントエンドを高速デプロイできる最適解でした。一方バックエンドは、サーバーレス関数（AWS Lambda等）ではLaTeXの重い処理の際に容量制限やタイムアウトエラーの壁にぶつかります。そのため、巨大なDockerコンテナを安定してホスティングでき、かつ無料枠内で運用可能なRenderのWeb Serviceを採用し、フロントとバックでインフラを適材適所に分離しました。
